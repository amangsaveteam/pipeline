# WORKFLOW-UPGRADE：可执行的 Codex 协作流程

Status: INTERNAL_TOOLING_DESIGN
Version: 1.0

## 目标与授权

把现有五角色模板补成可在本地 Git 项目复用、可验证、可恢复的研发流程。用户已请求完善当前流程，授权当前内部脚本、测试和说明的可逆修改；本设计不是用户对未来应用公开契约的批准。本任务不伪造 `contract.lock.json` 或审批身份。

## 范围

- REQ-001：使用 Python 3.10+ 标准库提供单一 CLI；任务初始化创建独立目录、manifest、契约模板及报告模板，记录 Git 基线；拒绝重复 ID、目录穿越及覆盖已有任务。
- REQ-002：任务保留阶段和历史，提供状态查看、合法阶段推进与门禁检查。规范阶段为 INTAKE → CONTRACT_DRAFT → CONTRACT_REVIEW → IMPLEMENTING → TESTING → VERIFYING → REVIEWING → DOCUMENTING → FINAL_GATE → READY_FOR_MR；任何必需证据缺失应非零退出，不能自动写成成功。
- REQ-003：契约冻结要求非空实际审批引用、三个完整契约文件；拒绝占位内容、重写已有锁及哈希漂移。锁只记录审批引用，不能验证审批人身份。实现开始及后续门禁均验证锁。
- REQ-004：每个写入阶段开始保存文件内容快照，结束按角色 allowlist 核查相对变化；应支持已存在未提交/未跟踪文件的工作区，并发现新增、删除、修改、重命名两端及符号链接变化。未发生变化的历史脏文件不应归咎当前角色。快照是事后检测，不是隔离。
- REQ-005：执行 manifest 指定的检查命令，保存 argv、工作目录、起止时间、退出码、日志及被检查内容的指纹；命令以 argv 运行且不隐式 shell，超时/找不到命令/非零均失败。验证门禁拒绝空检查列表、失败或已过期证据。执行前仍由主 Agent 判断命令在用户授权范围内。
- REQ-006：各阶段必须有相应报告；实现报告含变更与需求映射，测试报告将必需 AC 映射到实际结果，Review 必须 approved 且无未解决的阻塞级/高优先级发现，文档报告必须完成。必需验收未运行不可放行；可选硬件验收需显式列明并保留 NOT_RUN_HARDWARE，不能伪造 PASS。
- REQ-007：产品缺陷退回 IMPLEMENTING，测试缺陷退回 TESTING；每次返工记录原因、清除受影响的成功证据、最多两轮。提供显式 BLOCKED 与恢复；恢复重跑原有门禁，不能跳阶段或重置返工计数。公开契约变更保留旧版本，以关联的新任务重新审批，不覆盖锁。
- REQ-008：最终门禁重跑检查、验证契约/角色范围/报告并生成可评审的交付摘要；READY_FOR_MR 仅表示可准备 MR，不代表已推送、创建 MR、合并或部署。
- REQ-009：用临时 Git 仓库的独立自动化测试覆盖完整正常路径及关键拒绝路径。提供中文快速开始、可复制提示词、阶段/返工图和可选择接入的 GitLab CI 示例。CI 对选定任务执行真实门禁，不能静默跳过缺锁任务。

## 非目标与约束

不实现 Webhook 服务、持续运行的无人值守 Agent 后端、凭据管理、自动部署或机器人动作；不强制用户提交现有更改，不更改项目外文件。CLI 是状态与证据工具，Agent 委派仍由主 Codex 会话完成。现有 Codex 配置须核对当前官方文档；配置模板不会自动加载到已经运行的会话。

当前模板放在 `pipeline/codex_agents_workflow/`，Git 根在 `pipeline/`；正式使用语义是部署后 `.workflow/`、`.codex/` 与 `AGENTS.md` 同属目标 Git 根，CLI 应通过 `--root` 或明确 cwd 校验这一点。本任务是 maintenance 开发记录，不纳入正式业务任务 CI；集成测试仅在临时独立 Git 仓库提交，不提交当前用户工作区。CI 应显式选择目标业务任务，选错/缺锁时失败。

## 完成定义

全部必需自动化测试通过；说明命令与实际 CLI 一致；审查发现已解决或明确保留；说明脚本检测与真实权限隔离、审批认证之间的界限。
