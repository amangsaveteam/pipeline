# 设计假设与后续选择

- ASSUMPTION：当前交付优先为本地 Codex 多 Agent 流程。GitLab 只提供可合并到现有配置的 CI 示例；若用户选择 Issue 自动触发，后续需明确仓库、触发器与服务运行环境。
- ASSUMPTION：模板面向通用研发，并保留 ROS2/硬件测试约束；无具体业务应用、公开 API 或真机动作需要本次变更。
- DECISION：内部工具设计由主 Agent 在用户已授权的改进范围内推进；本目录不冒充已批准应用契约，不生成假的用户批准记录。
- DECISION：实际项目的公开需求/接口仍须有真实批准后冻结；新契约版本采用关联新任务，保留旧锁。
- DECISION：只使用 Python 标准库。契约 YAML 可作为哈希锁定的原始文本，验收 ID/检查配置使用 manifest 的显式结构；若实现需要解析完整 YAML，先避免新增依赖或另行说明。
- LIMITATION：共享工作区的快照是检查点检测；无法防止中途写入再恢复，也不能认证报告作者或审批人。更强的隔离与审批须由外部容器/受保护 GitLab 流程提供。
- LIMITATION：测试工具只能证明已运行的命令及检查内容；测试是否充分仍需独立测试 Agent 和 Review。
