# 主线程调度与恢复

只有主 Codex 线程推进阶段、执行返工和恢复。Agent 返回产物和证据；角色完成不等于整项任务完成。阶段以 manifest 为准，主线程通过 CLI 修改，不能手改 `stage`、`history` 或快照跳过失败。

| 阶段 | 工作负责人 | 退出条件 |
|---|---|---|
| INTAKE | 主线程 | 明确范围，配置权限、必需 AC 和真实检查命令 |
| CONTRACT_DRAFT | requirement | 四份契约材料完整、无模板占位符，阶段范围通过 |
| CONTRACT_REVIEW | 主线程及批准者 | 具体版本已有真实批准、冻结锁有效、必需 AC 可对应；本阶段只新增锁 |
| IMPLEMENTING | coding | 实现报告 completed、需求映射非空、无 blocker、范围通过 |
| TESTING | testing | 独立测试完成、必需 AC 对应真实成功检查、范围通过 |
| VERIFYING | 主线程 | 契约、报告、新鲜检查证据通过；只读复核 |
| REVIEWING | review | approved，无未解决 blocker/high；审查只读，报告由主线程归档 |
| DOCUMENTING | documentation | 已通过审查，文档及报告完成，范围通过 |
| FINAL_GATE | 主线程/CI | 进入该阶段后重跑真实检查；所有角色范围、契约与报告通过 |
| READY_FOR_MR | 主线程 | summary.md 已生成；准备具体可评审的交付内容 |
| BLOCKED | 主线程/负责人 | 记录原因，解决后恢复原阶段，原门禁仍生效 |

## 分派包

每次只发送该角色需要的内容：任务 ID、当前阶段、契约版本/哈希、允许修改路径、相关文件与日志、应交付的报告、停止条件。限制读取范围，避免复制整段聊天或扫描无关仓库。

主线程最多并行两个子 Agent，且子 Agent 不继续委派。共享工作区的 coding/testing 写入串行；只读测试规划可以与实现并行。需要并行写入时先建立独立工作区并定义集成步骤，原生 `spawn` 不会自动隔离文件系统。

## 失败路由

| 失败类型 | 处理 |
|---|---|
| 产品实现缺陷 | `rework --role coding`，重做受影响的实现、测试、审查与文档 |
| 测试自身缺陷 | `rework --role testing`，保留实现报告，重做测试及后继证据 |
| 环境缺失/外部依赖受阻 | `block --reason ...`；解决后 `resume --reason ...`，重跑必要检查 |
| 越权改动/哈希漂移 | 保留证据并恢复未授权变更；不可把扩大 allowlist 或重写锁当作修复 |
| 公开契约或任务策略需要变化 | 保留旧任务及锁，创建关联的新任务重新确认受影响内容 |
| 文档不符 | 文档阶段先修正允许范围内的文档；若实现有误，交回 coding；不能改契约迁就实现 |

返工从 TESTING 至 FINAL_GATE 的任一适用阶段发起，共最多两轮。第三次返工请求将任务标为 BLOCKED；负责人决定缩小范围、补齐环境或创建关联后续任务，不能通过清零计数无限重试。

`resume` 恢复原阶段，检查契约和阶段范围，不清零返工次数；该阶段的完整退出条件在下一次 `check/advance` 继续执行。需要人工决策的阻塞未解决时，不把等待时间当成批准。

当前 CLI 的特殊状态只有 BLOCKED；公开契约变更通过关联新任务表达，没有 `CHANGE_REQUESTED` 或 `FAILED` 命令可调用。READY_FOR_MR 后发现新工作也使用后续任务，不手改旧任务阶段。

## 契约变更

1. 记录变更原因、旧任务 ID/锁哈希、受影响接口、兼容性和验收条件。
2. 保留旧契约及证据；必要时将尚未交付的旧任务标为 BLOCKED。
3. `init` 新任务，例如 `TASK-0001-v2`，在 INTAKE 设置配置，并在需求材料中关联旧任务。
4. 对确实改变的公开契约取得相应批准，生成新锁，再走实现、测试、审查及文档。

已经针对同一版本提供的批准直接沿用，不反复询问。用户明确授权的内部流程模板维护可按维护任务记录范围和验证，不伪造业务契约批准。微小文字修正由主线程判断适用流程，避免五角色空转。

## Git 与交付

`init` 保存基线 SHA，但不自动建分支或提交。任务分支/工作区按项目约定管理；阶段快照支持已有脏文件，不要求为启动流程先提交用户全部更改。并行用户或其它工具改动同样会被范围检查发现，应先协调归属。

按授权保存锁、manifest、快照、报告与必要日志，保证评审和 CI 能复现。提交前后内容不变时，已验证删除的文件不会因为暂存/提交而改变指纹。最终摘要只代表本地门禁结果，不能替代真实 MR 审批、远端 CI 或发布记录。

## ROS2/机器人项目的附加材料

在契约中写明 ROS 发行版、Python ABI、消息包/版本、topic/service/action 名称、QoS、字段单位、坐标系、错误与超时处理、RMW 和兼容性。软件测试与实机测试分别记录；模拟通过不能代替必须真实验证的行为。硬件、部署和生产访问按实际授权执行，`allow_hardware` 等字段只是任务声明，不是物理访问控制。
